# MEAnalyzer GUI Frontend

## Overview
This project provides a graphical user interface for **MEAnalyzer**, for analyzing Intel Engine and PMC/PCHC firmware. The application acts as a wrapper that communicates with a compiled executable version of MEAnalyzer via a background command-line interface. 

The current distribution is bundled with **MEAnalyzer v1.311.0 r377**.

## Features
*   **CLI Integration**: The application executes MEAnalyzer commands invisibly and captures output for the GUI.
*   **Configurable Parameters**: CLI arguments are fully definable within the `settings.ini` file, allowing users to modify flags such as `-skip`, `-exit`, or `-json`, if in the furutre these change in the main MEAnalyzer software.
*   **JSON Reporting**: All firmware analysis results are processed in JSON format (generated by MEAnalyzer) and can be viewed in full within the application.
*   **Automated Tool Discovery**: The software includes logic to automatically detect and load the compatible Intel Flash Image Tool (FIT) from the local directory `/FlashTool`.
*   **Firmware Search**: Integrated search functionality assists in locating matching Intel Management Engine firmware downloads via external website.

## Technical Configuration

### Folder Organization and FIT Loading
The application automates the preparation of the Intel Flash Image Tool (FIT) based on the detected firmware version. To utilize this feature, folders must be organized as follows:

*   **Root Directory**: Contains the main application and `meanalyzer.exe` along with it's dependancies.
*   **FlashTool Directory**: A folder named `FlashTool` must exist in the root.
*   **Sub-folders**: Each version of FIT should be placed in its own sub-folder within `FlashTool`. The application identifies the correct tool by matching the version string provided by MEAnalyzer with the sub-folder name (e.g., `FlashTool/FIT_v11.0.0.1202/`or simply `FlashTool/11.0.0.1202/`).

### Temp Directory Management
The application utilizes a dedicated `Temp` directory for all operations. 
*   **Automatic Purge**: Every time a new BIOS file is loaded or dropped into the application, the `Temp` directory is **completely emptied** to prevent file conflicts.
*   **Data Preservation**: Users must ensure that any work, such as modified BIOS images or extracted regions, are moved out of the `Temp` folder before loading a subsequent file.

## Intel Management Engine Cleaning Instructions
The application includes a standard workflow for cleaning the Intel Management Engine (IME):

1.  **Load Image**: Load the Intel BIOS image into the program; this initializes the `Temp` environment.
2.  **Locate Firmware**: Identify the matching ME firmware using the integrated search tool.
3.  **Prepare Region**: Copy the matching firmware to the `Temp` folder and rename it to `ME Region.bin`.
4.  **Decompile**: Launch the Flash Image Tool (FIT) and open the BIOS file located in the `Temp` folder to generate the decompression directory.
5.  **Configuration**: In FIT, navigate to Build Settings and set **Generate Intermediate Files** to "No". Save the configuration as `untitled.xml`.
6.  **Replace Binary**: Overwrite the original ME binary in the `decomp` folder with the new `ME Region.bin`.
7.  **Build**: Use the FIT "Build Image" function to generate the cleaned BIOS (`outimage.bin`).

## Usage

### Prerequisites
*   Python 3.x
*   PyQt5 library

### Installation and Execution
1.  Ensure `meanalyzer.exe` is present in the project root.
2.  Install the required dependencies:
    ```bash
    pip install PyQt5
    ```
3.  Run the application:
    ```bash
    python your_script_name.py
    ```
OR simply run the exe from the release section, ensuring `meanalyzer.exe` and all other dependancies are present in the project root.
